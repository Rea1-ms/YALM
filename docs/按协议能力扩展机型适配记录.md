# 按协议能力扩展机型适配记录

日期：2026 年 10 月 28 日。

这次把原来只按主板判断的入口扩展为“已核对的服务版本＋固件能力＋具体功能”。它可以复用同一协议覆盖多台机器，但没有把 27 个安装包直接视为 27 个已完成适配的机型。

## 当前范围

| --- | --- | --- |
| 旷世 16 Pro（专业版），主板 GM6PX0X（型号标识） | 保留原有模式、转速、保护、自定义与外设功能及其条件 | 原来尚未完成的硬件验证不因本次变更而完成 |

| 其他服务或未知固件分支 | 已有桥接连接和服务状态读取 | 未核对的控制和专用寄存器读取 |

安装包来源不等同于型号承诺。例如极光 S 的服务进入目录，只代表该文件所包含的普通分支可被识别；机器仍要通过下面的现场条件。

GCUBridge.exe（桥接文件）的版本是否已收录只影响静态解析和连接发现，不单独撤销上表中的写入能力。未知桥接版本解析成功后，已验证主板仍沿用原有功能；新识别的普通分支仍只开放三种预设；旧版和未识别的硬件协议仍保持只读。连接成功不能代替硬件协议识别，各项状态、保护和供电条件也继续生效。

## 如何识别

先核对厂商和已验证主板；未匹配固定适配的机械革命机型，再从已注册桥接服务的安装目录定位硬件服务文件，以同一只读句柄计算完整 SHA256（文件指纹）。版本号、桥接认证相同、营销名称相似，都不能替代这个检查。这里核对的是 GCUService.exe（硬件工作进程），其指纹未知时不会进入专用寄存器探测；GCUBridge.exe（桥接文件）能否解析连接资料仍独立判断。

普通分支必须同时满足：

1. 厂商标识为机械革命，硬件服务文件属于下表的前两项。
2. 64 位厂商注册表中的 AppType（应用类型）明确为 1 或 2；缺失、错误或 3 均不开放。官方虽然对缺失值使用默认值 1，这次新适配仍要求明确值。
3. 固件地址 1934 的第 6 位表示支持该风扇协议。
4. 地址 1856 的原始项目编号为 1～8、10～13、15、16、22 中的一项。商用、未知及需要二级映射的项目不套用此分支。

新识别的普通分支还要等到两路转速和两项保护都已读取且未过期，才允许预设模式操作。通用热保护触发时禁用；风扇安全保护沿用原有含义。狂暴模式仍要求明确的支持能力和系统接电状态。没有新增写寄存器路径。

## 识别失败时看什么

日志按实际检查阶段说明原因。某一步未通过时不继续后续寄存器探测，也不会把旧连接的动态资格沿用到本次连接。

| 日志内容 | 对应含义 |
| --- | --- |
| 厂商匹配、已验证主板或机型匹配 | 厂商未匹配时保持只读；已验证主板沿用现有适配；其他机械革命机型继续识别 |
| 未找到服务注册项、程序路径无效、文件名不符 | 无法从注册的桥接服务定位硬件工作进程 |
| 硬件工作进程文件不存在、权限不足、路径无效或读取失败 | 文件访问未成功，日志保留异常类型与错误码，不记录异常原文 |
| 硬件工作进程文件大小超出范围 | 只接受 64～67,108,864 字节，超出后不计算指纹 |
| 硬件工作进程指纹未匹配已核对样本 | 当前硬件协议未识别，保持只读；不影响桥接静态解析的尝试 |
| 应用类型缺失、无效、读取失败或分支不支持 | 分别说明厂商注册项缺失、应用类型值缺失、值不是双字整数、数值不在 1／2／3、读取权限不足、其他读取失败，或类型 3 使用不同模式编号；只有明确的 1 和 2 进入普通分支能力探测 |
| 固件能力读取报错或寄存器缺失 | 本次读取未取得完整能力依据；日志列出错误状态和缺失字段 |
| 风扇能力位未置位、原始项目号未匹配 | 当前固件不符合已核对的普通分支，日志保留实际能力值与项目号 |

日志显示协议匹配只说明软件已取得启用对应功能的依据；实际连接、状态回报和硬件效果仍需对应机器验证。

## 与上游思路的关系

G-Helper（华硕控制工具）通过统一固件接口查询支持情况，再处理型号差异；它也有大量具体型号修正。本次沿用这种分层方式，机械革命命令仍由自己的适配层发送。

厂商服务本身包含多套风扇协议。静态分析已发现两类实质差异：应用类型 3 会把游戏动作解释为极速；旧商用分支虽然接收极速动作，后续转换却可能落到均衡。因此不能只搜索到命令名称就启用按钮。

5.17.49.19 等新版硬件服务的保护机制与桥接不同，当前桥接静态恢复结果不能用于证明这些硬件服务等价。原来已验证主板的行为保留，其他主板尚未新增这些服务的控制资格。蛟龙两款、翼龙和迷你主机使用独立接口，本轮只继续核实协议，没有接入产品控制。

## 同步修正

- 模式、自定义、外设的资格分别传入控制器。完整状态回报不能自行获得写入资格，只读刷新仍可使用。
- 自定义窗口、托盘、键盘和更多设置遵守同一资格，不能从其他入口绕过。
- 每次新连接先断开旧会话，再重新识别。未知服务、能力消失或应用类型改变会撤销此前的动态资格。
- 诊断探针按能力选择读表；未知机器只采服务状态。曲线与额外寄存器转储仍只允许原已验证主板，并在报告中区分服务完整性与硬件完整性。

自动审批拒绝了“保护读取未核实但开放旧版模式控制”的方案，理由是保护状态未知时可能降低过热防护。实际实现采用旧版仅查看转速、所有控制禁用的范围。

## 验证和材料

新增检查覆盖完整服务指纹、全部单字节项目与能力组合、缺失与错误数据、应用类型、旧资格撤销、保护缺失和过期、界面和控制器的禁写，以及只读刷新。真实服务文件通过注入模拟寄存器进行检查；没有连接真实设备或发送硬件写入。
