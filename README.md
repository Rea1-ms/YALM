# YALM（机械革命助手）

这是从 G-Helper（华硕控制工具）0.289 改造的机械革命面板。旷世 16 Pro（专业版）、主板 GM6PX0X（型号标识）保留现有功能；其他机器按已核对的厂商服务、固件能力和项目分支识别，分别启用预设模式或转速读取。不能用安装包名称判断整机是否全部支持。

## 现在能做什么

- 从已安装的原版后台读取模式、温度和风扇控制占空比，并通过厂商驱动只读 EC（嵌入式控制器），每秒读取两路实际转速与保护位；接电状态从系统读取。
- 手动请求安静、均衡、狂暴模式，并等待后台回报。狂暴要求机型配置明确支持且已接通电源；两路实际转速不完整、过期或保护位触发时，模式切换会暂停。
- 发现其他控制界面运行、状态缺失或过期时暂停切换。程序不会自动调度，也不会安装、卸载或停止其他控制软件。
- 关闭主窗口后保留托盘，左键显示／隐藏，再次启动会唤回原窗口。右键可切换性能和显卡模式、操作自定义模式的风扇增强、打开设置及退出；勾选跟随实际状态，显卡保存目标另标“待重启”。
- 键盘标题行提供背光、屏幕叠加、功能键锁定和系统键锁定；更多设置保留背光亮度，另提供功能键提示、数字键盘锁定、触摸板切换键、关机供电、来电自动开机和窗口置顶。厂商开关等待新的目标状态回报后才改变显示，真实硬件效果仍需逐项确认。

**这一版仍依赖厂商闭源后台和驱动，不是完整的开源硬件驱动替代品。** 原版后台只提供风扇控制占空比，实际转速由本程序直接读取 EC。界面把两者分开显示；例如 31% 表示控制值，转速仍以独立读数判断。显卡温度有时不回报，缺失或过期显示“未收到”。

EC 读取控制码本身要求带写权限的设备句柄，但程序没有包含 EC 写入控制码，也不会通过这条路径切换模式或修改风扇曲线。

模式命令只在点击按钮时发送。10 月 24 日已用调试版真实窗口依次请求均衡、安静并取得后续服务回读；安静档控制值降至 55%，两路实际转速相应下降，观察时保护位未触发。狂暴方向切换和游戏负载仍待验证，不能据此认定已经解决风扇不转的问题。

## 运行

产物位置：`D:\Files\CSharp\YALM\artifacts\YALM\YALM.exe`。直接运行即可，不需要管理员权限或安装步骤；需要 .NET 10 Desktop Runtime（桌面运行时），本机已安装。

默认只连接本机 `127.0.0.1:13688`。目前已核对 13 种桥接文件，包含原有 5.17.49.6 基线，以及本次 27 个官网安装包中使用桥接服务的 23 个包；5.17.49.19 也在其中。自动发现先核对完整文件指纹，8 种受保护文件还会在内存中还原方法体并再次校验指纹，再静态读取认证信息。认证信息只保留在内存，不执行厂商程序集、不写入日志或配置。

这表示上述版本能够自动读取连接资料，不代表所有机型的控制功能都已适配。新增协议识别另外核对硬件服务文件：5.17.49.6 和 5.27.49.9 的已核对普通风扇分支，可在固件能力、应用类型、完整转速与保护状态满足条件时切换预设模式；其高级设置与外设写入仍禁用。3.4.15.0 服务仅增加真实转速读取，全部控制保持禁用。每次重新连接都重新识别，失败后撤销原有协议资格。

蛟龙两包、翼龙和迷你主机的四个包采用其他接口，尚未接入。桥接版本见 `docs/官网控制台多版本静态检查记录.md`（多版本检查记录）；控制能力、限制和验证结果见 `docs/按协议能力扩展机型适配记录.md`（本轮适配记录）。

如果桥接版本不同，程序仍会先尝试静态解析并连接读取；解析失败时底部会说明原因，日志保留组件版本与校验结果。未知版本不会据此开放硬件写入，也不会转为直接写入硬件寄存器。还可以用下列环境变量提供本次连接信息：

| 环境变量 | 含义 |
| --- | --- |
| `YALM_GCU_CLIENT_ID` | 客户端标识 |
| `YALM_GCU_USERNAME` | 用户名 |
| `YALM_GCU_PASSWORD` | 密码 |
| `YALM_GCU_PORT` | 本机端口，默认 13688 |

若设置了任何认证字段，就必须填写完整，不会静默改用自动发现。旧的 `MHELPER_GCU_*`（原连接变量前缀）仍兼容；只要存在任一 `YALM_GCU_*`（新连接变量前缀）变量，就整组采用新前缀，不与旧前缀拼接。不要把这些值提交到源码或保存到共享日志。

配置保存到 `%APPDATA%\YALM`（用户应用数据目录）。首次运行时可读取并迁移旧版配置，原文件保留，不会删除。

遇到连接问题，可从更多设置打开普通日志 `log.txt`（日志文件）。启动时自动记录助手和系统版本、机型与主板、屏幕缩放、当前用户注册表中可见的控制中心包版本，以及桥接服务和硬件驱动的安装与运行状态、硬件工作进程状态、组件版本、桥接文件校验结果。连接与订阅失败保留响应代码、异常类型及系统或网络错误码；状态可用性仅在变化时记录，不逐条写入温度和转速。日志在发布版中同样启用，无需开启调试模式，不包含客户端标识、用户名、密码、原始消息或异常原文。未发现应用包只表示此读取方式未找到，不能据此确认未安装。

可加 `--demo`（演示）查看布局，并打开“风扇与功耗”拖动示例曲线，不连接后台、不控制硬件。关闭面板只断开本程序连接，原版服务继续运行。

## 构建与验证

使用 .NET SDK（开发工具包）10.0.402，在项目根目录运行：

```powershell
dotnet build YALM.slnx -c Debug
dotnet run --project tests/YALM.Tests/YALM.Tests.csproj
dotnet run --project tests/YALM.UiTests/YALM.UiTests.csproj -c Release
.\Publish.ps1
```

在 Rider（开发工具）的运行配置下拉框选择“一键打包”，点击运行即可完成同样的发布、自检和压缩，无需手动输入命令。配置保存在项目的 `.run`（共享运行配置目录），使用本机已安装的 PowerShell 7（命令行工具）；换电脑后若安装位置不同，在配置中调整可执行文件路径即可。

最后一条生成单文件便携版，使用与 G-Helper（华硕控制工具）相同的发布方式：把程序、托管依赖和资源合入 `YALM.exe`（可执行文件），桌面运行时由目标电脑提供。仍需 .NET 10 Desktop Runtime（桌面运行时）及本机适配的厂商后台，不捆绑厂商驱动或认证配置。

脚本先在只含可执行文件的新目录里运行离线演示自检，通过后生成 `D:\Files\CSharp\YALM\artifacts\portable\YALM.exe`（单文件程序）与同目录的 `YALM-win-x64.zip`（分发压缩包）。压缩包只包含程序、许可证、来源与使用说明，不包含缓存和用户设置；运行程序只需可执行文件，公开分发时仍按来源说明提供对应源码和许可证。重复发布会更新这些产物，本轮缓存保留在 `.cache/publish`（发布缓存目录），可自行清理。

第二条是离线回归测试，使用模拟传输，不连接真实服务。`--smoke-test`（演示启动自检）只创建演示窗体并自动退出。`--startup-test`（正常流程启动自检）使用真实连接与正常界面，禁止模式切换，约 12 秒后自动关闭；它与普通窗口共用实例锁，避免同时占用同一认证槽位。`--probe`（只读探针）后接绝对输出文件路径，可在约 15 秒内记录服务状态、EC 实际转速和保护位；它不发送模式切换、风扇曲线或功耗命令。

启动异常会记录到 `%LOCALAPPDATA%\YALM`（用户本地应用数据目录），失败时尝试系统临时目录。记录仅含异常类型和调用位置，不包含异常原文或连接凭据。普通启动会提示记录位置，自检以非零退出码报告失败。

研究材料和验证范围见 `docs`（文档）目录。旧项目、研究材料、工具与依赖缓存已移至 `D:\Files\CSharp\YALM\.cache\MHelper`；旧发布文件在 `.cache\artifacts\MHelper`，本轮构建缓存和自检日志分别在 `.cache\build`、`.cache\validation`。移动清单和数量核对结果也保存在 `.cache`（缓存）目录，整个目录已排除版本控制。原始研究材料可能含厂商固定认证字符串，不应公开。

当前程序仍在 `artifacts\YALM`（发布目录），源码和配置保持原位。旧 `D:\Files\CSharp\MHelper` 目录因进程占用只保留空目录，未删除任何文件。下次构建会重新生成构建缓存；可复用的依赖包保留在 `.cache\MHelper\.nuget\packages`。
