# YALM（机械革命助手）

这是面向机械革命机型的 YALM 面板。旷世 16 Pro（专业版）、主板 GM6PX0X（型号标识）保留现有功能；其他机器按已核对的厂商服务、固件能力和项目分支识别，分别启用预设模式或转速读取。原始华硕机型适配源码已归档到 `.cache/asus_backup`，不再进入 YALM 编译目标。

## 现在能做什么

下面列出已接入的功能，不同机器的实际可用范围见下一节“适配范围”。

- 从已安装的原版后台读取模式、温度和风扇控制占空比，并通过厂商驱动只读 EC（嵌入式控制器），每秒读取两路实际转速与保护位；接电状态从系统读取。
- 手动请求安静、均衡、狂暴模式，并等待后台回报。狂暴要求机型配置明确支持且已接通电源；两路实际转速不完整、过期或保护位触发时，模式切换会暂停。
- 发现当前登录会话的机械革命控制中心、托盘组件或其他兼容控制界面运行时暂停写入，状态栏持续说明原因，启动和状态变化会记录日志。退出控制台及其托盘后，程序会自动重新检查；厂商后台服务仍需保留。状态缺失或过期时也会暂停切换，不会自动调度、安装、卸载或停止其他控制软件。
- 关闭主窗口后保留托盘，左键显示／隐藏，再次启动会唤回原窗口。右键可切换性能和显卡模式、操作自定义模式的风扇增强、打开设置及退出；勾选跟随实际状态，显卡保存目标另标“待重启”。
- 键盘标题行提供背光、屏幕叠加、功能键锁定和系统键锁定；更多设置保留背光亮度，另提供功能键提示、数字键盘锁定、触摸板切换键、关机供电、来电自动开机和窗口置顶。厂商开关等待新的目标状态回报后才改变显示，真实硬件效果仍需逐项确认。

**这一版仍依赖厂商闭源后台和驱动，不是完整的开源硬件驱动替代品。** 原版后台只提供风扇控制占空比，实际转速由本程序直接读取 EC。界面把两者分开显示；例如 31% 表示控制值，转速仍以独立读数判断。显卡温度有时不回报，缺失或过期显示“未收到”。

EC 读取控制码本身要求带写权限的设备句柄，但程序没有包含 EC 写入控制码，也不会通过这条路径切换模式或修改风扇曲线。

模式命令只在点击按钮时发送。10 月 24 日已用调试版真实窗口依次请求均衡、安静并取得后续服务回读；安静档控制值降至 55%，两路实际转速相应下降，观察时保护位未触发。狂暴方向切换和游戏负载仍待验证，不能据此认定已经解决风扇不转的问题。

## 适配范围

截至 2026 年 10 月 28 日，本批 27 个官网安装包中，23 个已经完成桥接连接资料的静态解析适配。实际服务连接、状态回报和硬件控制分别核对，不能把安装包数量当作已完整适配的机型数量。

`GCUBridge.exe`（连接桥接组件）负责连接资料；`GCUService.exe`（硬件工作进程）处理具体设备协议。桥接文件相同，机器仍可能使用不同的硬件服务、固件分支和能力配置。当前范围如下：

| 识别到的硬件或协议 | 当前读取范围 | 当前控制范围 |
| --- | --- | --- |
| 已验证的 GM6PX0X（主板型号） | 原有服务状态、两路真实转速及保护状态 | 保留已接入的模式、自定义曲线、部分功耗、键盘、显卡切换和快捷设置，仍需满足各项操作条件 |
| 5.17.49.6、5.27.49.9 已核对服务的普通风扇分支 | 服务状态、两路真实转速及保护状态 | 固件能力、应用类型和新鲜状态满足条件时开放三档预设模式；自定义功耗、曲线、键盘、显卡及其他外设写入尚未开放 |
| F1（机型名）3.4.15.0、30 系 4.17.47.13，以及 Umi（机型名）／F1 独显共用的已核对服务 | 服务状态及两路真实转速；保护状态保持未知 | 全部写入尚未开放 |
| Code01（机型名）、S2Air（机型名）、无界 14 锐龙版的已核对旧商用服务 | 共享内存配置明确开启、项目编号为 1～16 时读取两路真实转速 | 全部写入尚未开放 |
| 蛟龙 16、蛟龙 16 Pro（专业版）40 系独立接口 | 当前模式、两路真实转速；已核对新版还读取处理器温度 | 全部写入尚未开放 |
| 翼龙 16X（机型名）独立接口 | 当前模式；确认英伟达显卡后读取显卡温度 | 全部写入尚未开放；风扇与处理器温度仍未接入 |
| iminiPro（迷你主机）独立接口 | 当前模式、风扇 1／2；温度接口结构匹配时读取处理器温度 | 全部写入尚未开放；不推断风扇的处理器或显卡归属 |
| 其他尚未识别的硬件协议 | 连接成功后尝试读取服务实际回报，字段缺失时保留未知 | 尚未开放写入，也不套用其他机型的专用寄存器地址 |

剩余工作主要是新版硬件服务和写入协议适配。40 系、50 系及多款无界、星耀等包虽然已支持桥接解析，六种新版服务的关键硬件方法仍受保护，尚未新增通用控制资格。旧服务和独立接口本轮补充的是已核对字段的只读适配，保护、曲线、功耗与外设控制没有随之开放。

已验证主板沿用原有适配，不需要等待每个安装包的通用协议适配完成。例如，同样使用 5.17.49.19 控制台，主板匹配 GM6PX0X（已验证型号）时保留原有控制能力；其他主板则按硬件协议识别结果决定范围。桥接版本不同不会单独导致禁写。每次重新连接都会重新识别，失败时撤销此前动态取得的协议资格。

蛟龙两款、翼龙和迷你主机分属三类独立接口。没有可用桥接连接资料且未显式设置连接变量时，程序检查相应控制台的安装身份、完整文件指纹、管理方法参数和唯一固件实例，然后只查询已核对字段。未匹配、错误或过期的字段保持未知；迷你主机采用“风扇 1／2”标签。重新连接会重新识别，读取状态不会取得写入资格。

上述范围结合当前代码、静态样本和离线检查整理，不代表这些机器的实际控制效果均已验证。桥接版本见 `docs/官网控制台多版本静态检查记录.md`（多版本检查记录）；协议条件和验证结果见 `docs/按协议能力扩展机型适配记录.md`（协议适配记录）和 `docs/剩余机型协议只读适配记录.md`（本轮补充记录）。

## 运行

产物位置：`D:\Files\CSharp\YALM\artifacts\YALM\YALM.exe`。直接运行即可，不需要管理员权限或安装步骤；需要 .NET 10 Desktop Runtime（桌面运行时），本机已安装。

默认只连接本机 `127.0.0.1:13688`。目前已核对 13 种桥接文件，包含原有 5.17.49.6 基线和上述 23 个包的桥接文件；5.17.49.19 也在其中。自动发现先核对完整文件指纹，8 种受保护文件还会在内存中还原方法体并再次校验指纹，再静态读取认证信息。认证信息只保留在内存，不执行厂商程序集、不写入日志或配置。

桥接版本未收录时，程序仍会尝试静态解析，取得连接资料后连接本机服务；失败时保留诊断原因。桥接版本是否已收录只影响连接发现，不单独禁用已适配功能；可写范围仍按硬件协议识别结果和各项操作条件决定，未识别的硬件协议保持只读。还可以用下列环境变量提供本次连接信息：

| 环境变量 | 含义 |
| --- | --- |
| `YALM_GCU_CLIENT_ID` | 客户端标识 |
| `YALM_GCU_USERNAME` | 用户名 |
| `YALM_GCU_PASSWORD` | 密码 |
| `YALM_GCU_PORT` | 本机端口，默认 13688 |

若设置了任何认证字段，就必须填写完整，不会静默改用自动发现。旧的 `MHELPER_GCU_*`（原连接变量前缀）仍兼容；只要存在任一 `YALM_GCU_*`（新连接变量前缀）变量，就整组采用新前缀，不与旧前缀拼接。不要把这些值提交到源码或保存到共享日志。

配置保存到 `%APPDATA%\YALM`（用户应用数据目录）。首次运行时可读取并迁移旧版配置，原文件保留，不会删除。

遇到连接问题，可从更多设置打开普通日志 `log.txt`（日志文件）。启动时自动记录助手和系统版本、机型与主板、屏幕缩放、当前用户注册表中可见的控制中心包版本，以及桥接服务和硬件驱动的安装与运行状态、硬件工作进程状态、组件版本、桥接文件校验结果。硬件协议识别还会说明厂商和主板匹配、服务文件定位、访问、尺寸与指纹，区分应用类型缺失、无效、读取失败或分支不支持，并记录能力读取错误、缺失字段、能力位或项目编号不匹配等原因。连接与订阅失败保留响应代码、异常类型及系统或网络错误码；状态可用性仅在变化时记录，不逐条写入温度和转速。日志在发布版中同样启用，无需开启调试模式，不包含客户端标识、用户名、密码、原始消息或异常原文。未发现应用包只表示此读取方式未找到，不能据此确认未安装。

可加 `--demo`（演示）查看布局，并打开“风扇与功耗”拖动示例曲线，不连接后台、不控制硬件。关闭面板只断开本程序连接，原版服务继续运行。

## 构建与验证

使用 .NET SDK（开发工具包）10.0.402，在项目根目录运行：

```powershell
dotnet build YALM.slnx -c Debug
dotnet run --project tests/YALM.Tests/YALM.Tests.csproj
dotnet run --project tests/YALM.UiTests/YALM.UiTests.csproj -c Release
.\Publish.ps1
```

在 Rider（开发工具）的运行配置下拉框选择“一键打包”，点击运行即可完成同样的发布、自检和压缩，无需手动输入命令。配置保存在项目的 `.run`（共享运行配置目录），使用本机已安装的 PowerShell 7（命令行工具）；换电脑后若安装位置不同，在配置中调整可执行文件路径即可。

最后一条生成单文件便携版：把程序、托管依赖和资源合入 `YALM.exe`（可执行文件），桌面运行时由目标电脑提供。仍需 .NET 10 Desktop Runtime（桌面运行时）及本机适配的厂商后台，不捆绑厂商驱动或认证配置。

脚本先在只含可执行文件的新目录里运行离线演示自检，通过后生成 `D:\Files\CSharp\YALM\artifacts\portable\YALM.exe`（单文件程序）与同目录的 `YALM-win-x64.zip`（分发压缩包）。压缩包只包含程序、许可证、来源与使用说明，不包含缓存和用户设置；运行程序只需可执行文件，公开分发时仍按来源说明提供对应源码和许可证。重复发布会更新这些产物，本轮缓存保留在 `.cache/publish`（发布缓存目录），可自行清理。

第二条是离线回归测试，使用模拟传输，不连接真实服务。`--smoke-test`（演示启动自检）只创建演示窗体并自动退出。`--startup-test`（正常流程启动自检）使用真实连接与正常界面，禁止模式切换，约 12 秒后自动关闭；它与普通窗口共用实例锁，避免同时占用同一认证槽位。`--probe`（只读探针）后接绝对输出文件路径，可在约 15 秒内记录服务状态、EC 实际转速和保护位；它不发送模式切换、风扇曲线或功耗命令。

启动异常会记录到 `%LOCALAPPDATA%\YALM`（用户本地应用数据目录），失败时尝试系统临时目录。记录仅含异常类型和调用位置，不包含异常原文或连接凭据。普通启动会提示记录位置，自检以非零退出码报告失败。

研究材料和验证范围见 `docs`（文档）目录。旧项目、研究材料、工具与依赖缓存已移至 `D:\Files\CSharp\YALM\.cache\MHelper`；旧发布文件在 `.cache\artifacts\MHelper`，本轮构建缓存和自检日志分别在 `.cache\build`、`.cache\validation`。移动清单和数量核对结果也保存在 `.cache`（缓存）目录，整个目录已排除版本控制。原始研究材料可能含厂商固定认证字符串，不应公开。

当前程序仍在 `artifacts\YALM`（发布目录），源码和配置保持原位。旧 `D:\Files\CSharp\MHelper` 目录因进程占用只保留空目录，未删除任何文件。下次构建会重新生成构建缓存；可复用的依赖包保留在 `.cache\MHelper\.nuget\packages`。
